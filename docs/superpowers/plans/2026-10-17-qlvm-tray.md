# qlvm Tray + App Whitelist Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A waybar-tray icon (`qlvm-tray`) listing VMs with run state, per-VM whitelisted-app submenus and actions (start/stop/sync, app click = start-if-stopped → waypipe), plus the Qubes-style per-VM app whitelist (CLI + Fyne "Apps" tab + daemon methods) that filters everywhere.

**Architecture:** Whitelist core in `internal/apps` (file per VM in the existing desktop cache, absent = all apps, shared sync helper preserving it). CLI `apps whitelist` subcommands operate file-side. Daemon gains `ListApps`/`SyncApps`/`SetAppWhitelist` for the pure-D-Bus GUI. `internal/tray` computes the menu tree from polled D-Bus state + cache; `cmd/qlvm-tray` renders it with `fyne.io/systray` (StatusNotifierItem + DBusMenu, session bus). GUI gets an Apps tab in the existing VM details dialog.

**Tech Stack:** Go, godbus (system bus), `fyne.io/systray` (session bus SNI/DBusMenu; already in go.mod as indirect → promote to direct), Fyne v2 (GUI), sshx/waypipe (launch + sync), containerized cgo build.

**Spec:** `docs/superpowers/specs/2026-10-17-qlvm-tray-design.md` (read it — builder calls 1–13 are binding).

## Global Constraints

- `sudo make container-build` is the completion gate for code tasks (AGENTS.md): plain `go build` without `libxl` is not sufficient.
- Live-verify D-Bus with `busctl call` (not just introspect) — godbus doesn't support introspection.
- No shelling out to management CLIs; native planes only (godbus, xenlight, sshx, waypipe exec).
- No vendor names / real IPs in the repo (CSB); dom0 is ostree (no ad-hoc `dnf`).
- Cache dir `/var/lib/qlvm/desktop-cache/<vm>/`; whitelist file `whitelisted-appmenus.list` (one `.desktop` basename per line; absent file = all apps; empty list → delete file).
- `qlvm vm run` / tray are **user-session** commands; the daemon is root.
- VM states (agent.VMInfo.State): `running|stopped|dying|paused|blocked`; CLI treats `== "running"` as up.
- Tray: ssh connect mode only (builder call 11); 2 s poll, rebuild menu only on computed-tree change (builder call 3); errors via tooltip (builder call 4).

## Review Focus

1. **Whitelist clobbered by sync** — a "Sync" (CLI, daemon, or tray) must leave an existing whitelist byte-identical; test pins it (Task 1).
2. **Ambiguous / unknown app name in `whitelist add|remove`** — `firef` matching exactly one app succeeds; two matches errors listing both; zero matches names the cache dir + suggests `qlvm apps sync` (Task 2).
3. **Tray with the daemon down** — first `ListVMs` error renders an error-state menu (one disabled item) and keeps polling; no crash, no icon flap (Task 5).
4. **App launch on a stopped VM** — start → wait-control → waypipe order; a start failure leaves a clear tooltip and doesn't leave the menu in a half-busy state (Task 5).
5. **GUI Save with everything unchecked** — sends an empty whitelist list, which must round-trip to *file deleted* = all apps visible (Tasks 3+4).

### Task 2: CLI `qlvm apps whitelist` + CLI sync through `SyncCache`

**Files:**
- Modify: `internal/cli/apps.go` (new `whitelist` subcommand group; `appsSyncCmd` → `apps.SyncCache`)
- Test: `internal/cli/apps_test.go`

**Interfaces:**
- Consumes: Task 1 `ReadWhitelist`, `WriteWhitelist`, `CachedApps`, `SyncCache`; existing `appsCacheDir` var, `vm.LoadMeta(vmDirOf(name))` existence check.
- Produces: `qlvm apps whitelist list|add|remove|clear <vm>`.

Matching rule (for add/remove args): case-insensitive match against each cached app's **basename** (e.g. `Firefox.desktop`) or **Name**; a unique basename prefix (e.g. `firef` → `firefox.desktop`) is accepted; 0 or >1 matches → error (list candidates when >1; when 0, name the cache dir and suggest `qlvm apps sync <vm>`).

Semantics (builder calls 2, 6):
- `list <vm>`: `# whitelist active (N/M apps)` header when a file exists, then `<basename>.desktop  <Name>` per visible app; without a file, no header (all apps).
- `add <vm> <app...>`: base set = current whitelist if present, else the full cached set; add matches; write.
- `remove <vm> <app...>`: same base set; remove matches; empty result deletes the file (all apps).
- `clear <vm>`: delete file (all apps); succeeds even if absent.

### Task 6: `cmd/qlvm-tray` binary + systemd user unit

**Files:**
- Create: `cmd/qlvm-tray/main.go`, `cmd/qlvm-tray/embedded/qlvm-tray.service`, `cmd/qlvm-tray/icon.go`
- Modify: `Makefile` (build + install `qlvm-tray` alongside the other binaries), `go.mod`/`go.sum` (`fyne.io/systray` → direct)

**Interfaces:**
- Consumes: Task 5 `ComputeMenu`, `Signature`, `Actions`; `agent.NewClient()`; `fyne.io/systray` (`systray.Run(onReady, onExit)`, `AddMenuItem`, `AddSubMenuItem`, `SetIcon([]byte)`, `SetTooltip`, `MenuItem.ClickedCb`).
- Produces: `qlvm-tray` binary; `qlvm-tray install-system-files` writes `~/.config/systemd/user/qlvm-tray.service` (embedded: `After=graphical-session.target`, `WantedBy=default.target`, `Restart=on-failure`) and runs `systemctl --user daemon-reload && systemctl --user enable --now qlvm-tray.service`.

Behavior:
- onReady: build `Actions` (agent client on system bus; cache dir from `-cache-dir`, default `/var/lib/qlvm/desktop-cache`), render menu from Task-5 model.
- Poll loop: `ListVMs` every 2 s; on error (daemon down) render one disabled item `qlvm agent unreachable: <err>` (Review Focus 3); on success recompute `MenuTree`; apply to systray only when `Signature()` changed (rebuild children in place).
- Item clicks dispatch to `Actions` in goroutines; results via `Notify` → `systray.SetTooltip`; busy items disabled while an action for that VM is in flight.
- Icon: small embedded monochrome PNG (builder call 8).
- SIGTERM/SIGINT + `Quit` → `systray.Quit()` (SNI unregister).
