Goal & Architecture

Goal: Add a lightweight Kubernetes control plane (kube-apiserver + kine/SQLite) and a controller binary to qlvm, exposing VMs, Templates, and Domains as CRDs with watch-based reconciliation. No kubelet, no scheduler, no container runtime — just the API server and qlvm's controller.

Architecture: Three processes at runtime: kine (SQLite etcd shim) → kube-apiserver (REST API) → qlvm-controller (controller-runtime watching CRDs, calling existing xenlight/libovsdb/godbus libraries). A new qlvm k8s CLI group starts/stops the control plane. Existing qlvm vm/template commands continue to work unchanged; users manage CRs via kubectl or the CLI.

Tech Stack: Go (existing), controller-runtime, k8s.io/client-go, k8s.io/apimachinery, k8s.io/apiextensions-apiserver, controller-gen, kine binary, kube-apiserver binary. Existing qlvm packages (xenctl, ovn, ovs, template, vm, config) are reused as actuators.

References: k8senv (subprocess management pattern), kine (SQLite etcd shim).

Global Constraints

  • Module path: github.com/jcpowermac/qlvm (unchanged)
  • TDD: every task starts with a failing test
  • Lint: golangci-lint run must pass at every commit
  • Clean repo: no vendor names, no real IPs (example space 10.100.x / 192.168.1.x only)
  • os/exec exception: subprocess management of kine/kube-apiserver is permitted (control plane infrastructure, not management-plane operations)
  • Integration tests: //go:build integration, never run in default go test ./...
  • Binary distribution: kine and kube-apiserver are external binaries (not embedded)
  • Storage: Single SQLite file at /var/lib/qlvm/k8s/kine.db
  • API group: qlvm.io, version v1
  • Namespace: All CRs in default namespace

CRD Model

VM (qlvm.io/v1 VM)

apiVersion: qlvm.io/v1
kind: VM
metadata:
  name: work-laptop
spec:
  template: fedora-44-a1b2c3d4    # template CR name or dir slug
  domain: work                    # domain CR name
  type: app                       # app | disposable
  memoryMB: 4096
  vcpus: 2
  mounts:                         # optional
    - host: /home/user/projects
      guest: /mnt/projects
  workspaceSizeMB: 0              # optional, 0 = none
status:
  state: running                  # absent | created | running | stopped
  ip: 10.100.1.10
  mac: aa:bb:cc:dd:ee:ff
  uuid: ...
  conditions:
    - type: Ready
      status: "True"
      reason: Running
      message: VM is running

Review Focus

  1. kine/apiserver startup ordering: apiserver must not start until kine's TCP port is ready and serving. → test in Task 2
  2. CRD installation before controller start: controller must not begin watching until all 3 CRDs are Established. → test in Task 3
  3. VM controller idempotency: reconcile must be safe to call multiple times with the same spec (no duplicate OVN ports, no duplicate libxl domains). → test in Task 4
  4. Template bake failure handling: if image-builder fails, status must be failed with error message, and CR must be re-queueable. → test in Task 5
  5. Graceful shutdown: qlvm k8s stop must stop controller → apiserver → kine in reverse order, preserving SQLite DB. Running VMs must NOT be killed on control plane stop. → test in Task 7
  6. Port binding conflicts: if ports 6443 or 2379 are in use, startup must fail with a clear error, not hang. → test in Task 2
